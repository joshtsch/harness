# Security policy

Please do not publish credentials, private keys, personal records, or raw
external-tool output in an issue or change request.

After publication, report a suspected vulnerability through
[GitHub private vulnerability reporting](https://github.com/joshtsch/harness/security/advisories/new).
The publication checklist requires enabling and verifying this form. Include
enough detail to reproduce the problem, but redact credentials and personal
data. Do not open a public issue for an active security problem. Before the
public release, reports stay within the private repository's authorized
maintainer channels.

The harness keeps credentials and private project configuration outside tracked
files. See [data safety](docs/agents/data-safety.md) and [secure documents](docs/agents/secure-documents.md)
for storage rules.
